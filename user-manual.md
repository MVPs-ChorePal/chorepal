## 1. Introduction
ChorePal is a mobile application designed to solve the accountability gap in modern household management. Traditional methods of chore tracking rely on honesty-based manual check-offs, which often lead to disputes or incomplete tasks. ChorePal disrupts this model by implementing a rigorous, multi-stage evidence pipeline powered by Artificial Intelligence.

By integrating **AWS Rekognition** for computer vision and **Supabas**e for real-time cloud data synchronization, ChorePal ensures that tasks are physically verified before rewards are dispensed. The system operates on a sophisticated state-machine architecture, transitioning chores from "To-Do" (setup) to "Pending" (work in progress) to "Completed" (AI-verified), and finally "Approved" (parent-confirmed). This document serves as the comprehensive technical and operational guide for users, administrators, and developers.

## 2. System Requirements
### 2.1 Hardware Requirements
- **Mobile Phone:** A modern smartphone running iOS 15.0+ or Android 11.0+.
- **Processor & RAM:** A minimum of 4GB RAM is required; 8GB is highly recommended for handling concurrent camera-to-cloud streams and AI feedback processing.
- **Camera Hardware:** Integrated rear-facing camera capable of 720p (1280x720) resolution or higher.
- **Storage:** 150MB of available local storage for application binaries and temporary image caching.

### 2.2 Software Requirements
- **Host Client:** The Expo Go application (version 54.0 or higher) must be installed on the mobile device.
- **Network:** High-speed internet access (Wi-Fi or 4G/5G) with a minimum upload speed of 5Mbps is required for binary blob transfers to AWS S3.
- **Development Tools:** For administrators/developers, Node.js (LTS Version 20.x) and npm must be installed on the workstation.

## 3. Installation Guide
### 3.1 Repository Cloning
Initialize the local environment by cloning the source code and navigating to the frontend application directory:
> git clone https://github.com/MVPs-ChorePal/chorepal.git   
> cd chorepal/Application/Frontend  

### 3.2 Dependency Deployment
ChorePal utilizes advanced libraries for native camera access and cloud communication. Install these via the Node Package Manager:
> npm install

### 3.3 Security Configuration
**CRITICAL SECURITY NOTE:** ChorePal follows a "Zero-Trust" model. API keys and cloud secrets are never stored in the repository. You must manually create a local environment file in the Application/Frontend directory.

Create a file named .env.local and input the following variables:
- EXPO_PUBLIC_SUPABASE_URL
- EXPO_PUBLIC_SUPABASE_ANON_KEY
- EXPO_PUBLIC_AWS_S3_BUCKET_NAME
- EXPO_PUBLIC_AWS_REGION

**Note*: The EXPO_PUBLIC_ prefix is mandatory for Expo to expose these variables to the mobile runtime.

### 3.4 Launching the Metro Bundler
Execute the command below to start the local development server:
> npx expo start --clear

## 4. Getting Started
ChorePal utilizes a role-specific, unified authentication gateway. This design ensures that users are presented with the appropriate interface and security protocols from the moment they initialize the application.

### 4.1 Initializing the Application
1. Ensure the **Expo Go** application is active on your mobile device.
2. Scan the QR code generated by the development server.
3. The **ChorePal Splash Screen** will appear, during which the system performs a background check for existing sessions (Cache Check). If no active session is detected, you will be directed to the primary Role Selection screen.

### 4.2 Parent Onboarding & Login
If you are the primary administrator of a household:

1. Select the Parent path from the landing screen.
2. **Unified Credentials:** Enter your Full Name, Email Address, and Password.
    - **New Users:** The system will automatically create your administrative profile and generate a unique Family ID.
    - **Returning Users:** The system will verify your credentials and restore your existing household data.
3. **Secret Code Generation:** Upon successful authentication, navigate to the Account tab to retrieve your household code. This code is required to link child accounts to your dashboard.

### 4.4 Child Onboarding & Synchronization
If you are a worker user within a household:

1. Select the Child path from the landing screen.
2. **Unified Gateway:** Enter your Full Name and Password to initialize or access your profile.
3. **Household Synchronization:** Upon your first login, the system will prompt you for the household code
    - Enter the code provided by your Parent.
    - This action creates a permanent relational link in the database, allowing you to view tasks specifically assigned to your Family ID.
4. **Persistent Access:** Once linked, subsequent launches will bypass the code entry screen and take you directly to your personalized Chore Board.

## 5. Features & Functions

### 5.1 The AI Verification Pipeline (Child Workflow)
This is the central functional pillar of ChorePal, it uses a three-stage state machine to track physical work progress.

#### 5.1.1 Phase 1: Documentation
The child selects an assigned task and snaps a "Before" photo of the mess (e.g., a sink full of dishes). The app converts this to a binary blob and uploads it to AWS S3. The database updates the chore status to Pending. This documents the starting state for parental review.

#### 5.1.2 Phase 2: Verification
Once the child completes the manual cleanup, they return to the app and capture an "After" photo. The app performs a secure "Handshake" with a Supabase Edge Function, passing the image reference and the specific Chore ID.

#### 5.1.3 Phase 3: AI Reasoning & Result
The AI Agent, running on Deno in the cloud, analyzes the image against the "Target Label" (e.g., "Dishware") set by the parent.
- **Success:** If the AI confirms the target is present, the chore status moves to **Completed**.
- **Failure:** If a mismatch is detected, the AI provides specific natural-language feedback (e.g., "I see a table, but no dishes"). The child is prompted to retry, and an **Attempt Number** is incremented in the history log.

## 6. Household Economy & Virtual Ledger
Every transaction in ChorePal is recorded in a permanent, immutable ledger to ensure mathematical accuracy.

### 6.1 Virtual Wallet
Children earn points upon a Parent's final approval. These points are stored in a current_balance column in the users table, which is accessible across all devices in real-time.

### 6.2 Point Transactions
Every time a chore is approved, a new row is created in the transactions table. This creates a "Bank Statement" for the child, listing the date, chore title, and points earned. This prevents data loss if a chore is later deleted.

## 7. Technical Architecture Deep-Dive
ChorePal utilizes a decoupled, cloud-native architecture to ensure security and data isolation.

### 7.1 Database Normalization
Data is divided into two primary tables to support historical tracking:
- **chores Table:** Stores the task definition, point value, and current state.
- **chore_analysis Table:** A persistent log of every attempt a child makes. This allows parents to review the child's improvement over time.

### 7.2 Serverless Logic (Edge Functions)
By offloading AI processing to **Supabase Edge Functions**, ChorePal keeps the mobile client lightweight and protects AWS API keys from local extraction.

### 7.3 Data Isolation (RLS)
ChorePal implements strict **PostgreSQL Row Level Security (RLS)**. Every query is automatically filtered by family_id, ensuring that one household can never view the photos, balances, or chores of another household.

 
## 8. Troubleshooting & Error Resolution
1. Login "Stuck" on Logo; Stale cache or invalid refresh token. 
Press the Logout button to reset the session.

2. Image Rendering Failure; S3 URL mismatch or variable naming error.
Ensure the .env.local file uses the EXPO_PUBLIC_ prefix and your AWS bucket is set to "Public Read."

3. AI "Check Failed"; Poor lighting or incorrect camera angle.
Ensure the target object is well-lit and occupies the majority of the camera frame.

4. "Unmatched Route" Screen; Navigation folder naming conflict.
Verify that folder groups (e.g., (parent)) contain parentheses in the file system.

## 10. FAQ
**Q: Why does the app take two photos?**    
**A:** The "Before" photo acts as a baseline to prove the chore was actually needed. The "After" photo is the one analyzed by our AI Agent to verify the work was completed.

**Q: What is the "Attempt Number"?**    
**A:** This tracks how many times a child had to try before the AI (or parent) accepted the work. This helps track improvement in chore quality over time.

**Q: Can I change point values after a chore is created?**  
**A:** To maintain the integrity of the "Family Contract," point values are locked once a chore is assigned.
